真实影响行为的问题：`get_permissions` 被 `lru_cache` 缓存后，同一 `user_id` 的权限在进程生命周期内不会重新读取。管理员在运行中修改角色后，`can_delete` 仍按旧权限判断，可能继续允许已撤权用户删除，或拒绝刚授权用户。缓存键只有 `user_id`，也没有失效入口。

修改建议：

1. 去掉 `lru_cache`，每次调用 `load_user` 后取当前权限。若数据库压力可接受，这是最直接正确的做法。
2. 若必须缓存，给缓存加显式失效：角色变更时调用 `get_permissions.cache_clear()`，或按 `user_id` 精确失效。注意多进程部署下每个进程各有缓存，单进程清理不够，需要广播失效或改用共享缓存并带版本号/TTL。
3. 更稳妥的是缓存短 TTL，并接受最长一个 TTL 的权限延迟；这要求业务明确能容忍该延迟。

另外，`load_user` 返回 `None` 时这里会抛 `AttributeError`，建议明确处理用户不存在的情况。
