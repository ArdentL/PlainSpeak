这个想法值得先做小实验验证，核心价值不在“省调用”本身，而在于它把讨论预算集中到真正有分歧的题目上。下面按你的三个问题拆开说。

## 1. 具体可能解决什么问题

**主要问题：讨论成本与讨论收益不匹配。** 现在每题都跑两轮讨论，但很多题两个 Agent 初始答案一致，讨论大概率只是互相确认，收益低。你的方案把讨论触发条件设为“答案不一致”，相当于一个免费的置信度代理：一致 ≈ 高置信，不一致 ≈ 需要协商。

**次要问题：讨论引入的噪声。** 两轮讨论有时会让原本正确的 Agent 被说服改错（尤其当两个 Agent 能力相近、理由风格不同时）。只在分歧时讨论，能减少“一致但被讨论带偏”的情况。

**还有一个隐性收益：** 分歧率本身是个可观测指标。你可以顺带统计不同题型/难度下的分歧率，判断哪些场景值得上讨论、哪些直接单 Agent 就够。

## 2. 最容易失败在哪里

按风险从高到低：

1. **“答案一致”不等于“都对”。** 两个 Agent 可能共享同一个错误（同模型不同 prompt、同训练数据偏差），一致地错。这时省掉讨论就省掉了纠错机会。这是最大的风险，也是实验必须量化的。
2. **答案格式不一致导致假分歧。** 数值题 `0.5` vs `1/2`、选择题 `A` vs `A.`、开放题措辞不同但语义相同——这些会被误判为分歧，触发不必要的讨论，省调用效果打折。需要先做答案归一化。
3. **分歧题上两轮讨论本身不够。** 如果分歧题恰好是难题，两轮讨论可能也收敛不了，你的方案在“该讨论的题”上并没有比基线更强，只是没更差。
4. **触发阈值太粗。** 二值“一致/不一致”丢掉了信息。可以后续考虑用答案相似度或 Agent 自报置信度做更细的触发，但第一版先别加。

## 3. 明天能跑的小实验

目标：验证“只在分歧时讨论”相对“每题都讨论”和“完全不讨论”的取舍。用你现有代码，加一个路由分支即可。

**数据：** 100–200 题，选你已有评测集里答案可自动判定的部分（选择题或数值题最省事）。如果有多难度分层，每层都采一些。

**三个条件，同一批题：**

- A：独立回答，不讨论（下界，省调用但无纠错）
- B：每题两轮讨论（你现在的基线）
- C：你的方案——先独立回答，一致则直接采用，不一致才跑两轮讨论

**记录指标：**

- 准确率（A/B/C 各自）
- 总 LLM 调用次数（C 相对 B 省了多少）
- 分歧率（C 里触发讨论的比例）
- **关键诊断：一致但错误的题数**（C 相对 A 没纠回来的部分）——这直接量化风险 1
- 分歧题上 C 的准确率 vs B 在同样这些题上的准确率（讨论有没有用）

**判读标准（提前定好，避免事后找理由）：**

- 若 C 准确率 ≥ B − 1~2 个点，且调用数明显下降 → 想法成立，值得继续
- 若 C 明显低于 B，看差距是否集中在“一致但错”的题上 → 说明需要更细的触发信号（置信度/相似度），而不是放弃想法
- 若分歧率极低（比如 <10%）→ 说明两个 Agent 太同质，讨论本身价值就有限，先换 Agent 多样性再谈路由

**实现上注意两点：** 先做答案归一化再判一致；把“一致但错”的题单独存下来人工看几条，判断是共享偏差还是归一化漏判。

这个实验一天能跑完，而且不管结果正负都能告诉你下一步该调触发信号还是调 Agent 多样性。
