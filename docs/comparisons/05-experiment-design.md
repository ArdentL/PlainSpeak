# 设计实验，检查第二轮提供检索证据是否有用

[返回场景列表](README.md) · [调用记录](data/05-experiment-design.json)

## 用户问题

我有一个想法：让三个 Agent 在第二轮讨论时才拿到检索证据，第一轮先独立回答，最后汇总。现有代码已经支持三 Agent 讨论和检索开关。我想先判断“第二轮给证据”有没有用。请帮我设计一个小实验，明确对照、预算怎么对齐、看什么结果，以及什么结果会让你建议停止。

<h1>小实验设计：第二轮才给检索证据，值不值得？</h1>
<h2>1. 先明确你要验证的假设</h2>
<p>你的设计本质上是把&quot;检索证据&quot;从<strong>全程可用</strong>改成<strong>第二轮才注入</strong>。要判断它有没有用，需要拆成两个可证伪的问题：</p>
<ul>
<li><strong>H1（相对无证据）</strong>：第二轮给证据，是否比&quot;全程不给证据&quot;更好？</li>
<li><strong>H2（相对全程给证据）</strong>：第二轮给证据，是否不劣于（或优于）&quot;第一轮就给证据&quot;？</li>
</ul>
<p>只做 H1 容易得出&quot;有用&quot;的结论，但那可能只是&quot;有证据比没证据好&quot;，不能说明&quot;延迟给&quot;这个设计本身有价值。<strong>建议两个对照都做</strong>，否则结论会误导后续决策。</p>
<h2>2. 对照臂设计（4 个臂，最小充分集）</h2>

<p>D 臂很关键：如果 C ≈ D，说明第二轮的证据根本没被用上，你的&quot;延迟&quot;设计是无效的，只是碰巧第一轮有证据。没有 D，你无法区分&quot;延迟注入有效&quot;和&quot;第一轮注入就够&quot;。</p>
<p>如果预算紧张，最低配是 <strong>A / B / C</strong> 三臂，但要在报告里注明无法排除 D 的混淆。</p>
<h2>3. 预算对齐（这是最容易做错的地方）</h2>
<p>&quot;预算&quot;要分三层对齐，否则比较不公平：</p>
<ol>
<li><strong>Token 预算</strong>：每个臂的总 token 上限相同（输入+输出）。注意 B 臂第一轮就带证据，输入 token 天然更高——要么给所有臂相同的<strong>总</strong>预算并允许 B 臂第二轮少检索，要么按&quot;每轮预算&quot;对齐并单独报告总消耗。<strong>推荐前者</strong>，因为总成本才是你真正关心的。</li>
<li><strong>检索预算</strong>：C 臂只在第二轮检索一次，B 臂若两轮都检索就是两次。要么让 B 臂也只检索一次（第一轮检索、第二轮复用），要么明确记录检索次数差异并在分析中控制。<strong>建议统一为&quot;每任务最多一次检索&quot;</strong>，让差异只来自&quot;何时注入&quot;。</li>
<li><strong>轮次/调用预算</strong>：所有臂都是两轮讨论 + 一次汇总，Agent 数量、轮数、汇总 prompt 完全一致。唯一变量是证据注入时机。</li>
</ol>
<p>另外固定：同一批问题、同一模型版本、同一 temperature、同一检索器与 top-k、同一随机种子集（每问题跑 3–5 次取均值以降方差）。</p>
<h2>4. 看什么结果</h2>
<p><strong>主指标（决定去留）</strong></p>
<ul>
<li>任务准确率 / 正确率（按你的任务定义，最好有自动可判定的 ground truth）。</li>
<li>相对 A 的提升（H1）和相对 B 的差距（H2）。</li>
</ul>
<p><strong>机制指标（解释为什么）</strong></p>
<ul>
<li><strong>证据采纳率</strong>：第二轮回答中，最终结论是否引用了证据内容（可用 LLM 判官或关键词/引用检测）。这是判断&quot;延迟注入是否真被用上&quot;的核心。</li>
<li><strong>第一轮答案 vs 最终答案的翻转率</strong>：C 臂里有多少比例因第二轮证据而改变结论。翻转率高且翻转后更准 = 设计有效；翻转率低 = 证据没起作用。</li>
<li><strong>Agent 间分歧度</strong>：第一轮三 Agent 答案的一致性，以及第二轮后是否收敛。延迟证据的一个理论好处是&quot;先独立、后纠偏&quot;，这个指标能验证该机制。</li>
<li><strong>成本</strong>：总 token、检索次数、延迟（wall-clock）。</li>
</ul>
<p><strong>统计</strong>：每臂每问题多次运行，报告均值 ± 置信区间；用配对检验（同问题跨臂比较），样本量建议至少 50–100 题，否则差异会被噪声淹没。</p>
<h2>5. 什么结果会让你建议停止</h2>
<p>建议**停止（不做这个改动）**的信号：</p>
<ol>
<li><strong>C 不显著优于 A</strong>：延迟证据没带来可测收益 → 直接停。</li>
<li><strong>C 显著劣于 B</strong>：延迟注入损失了准确率，且差距超过你预设的实用阈值（比如 &gt;3–5 个百分点）→ 停，除非你有明确的成本理由。</li>
<li><strong>C ≈ D</strong>：说明收益来自&quot;第一轮有证据&quot;，第二轮注入是摆设 → 停，改回第一轮注入。</li>
<li><strong>证据采纳率低</strong>（比如 &lt;30%）：第二轮 Agent 基本无视证据 → 设计无效，停或先修 prompt。</li>
<li><strong>翻转率低但准确率也没提升</strong>：证据既没改变结论也没帮忙 → 停。</li>
<li><strong>成本不降反升</strong>：如果延迟注入没省下检索/token，却增加了复杂度和延迟 → 没有工程理由继续。</li>
</ol>
<p>建议<strong>继续/扩大实验</strong>的信号：C 显著优于 A、与 B 差距在阈值内（非劣）、证据采纳率和&quot;翻转后变准&quot;的比例都高——这时才值得投入更大规模验证或上线 A/B。</p>
<h2>6. 一个提醒</h2>
<p>你这个设计的隐含卖点是&quot;第一轮独立回答避免证据锚定，第二轮再纠偏&quot;。如果这是你的真实动机，<strong>除了准确率，一定要测&quot;锚定效应&quot;</strong>：比较 B 臂第一轮答案与最终答案的相似度 vs C 臂。如果 B 臂第一轮就被证据带偏、C 臂第一轮更独立，这才是延迟注入的独特价值，也是唯一能让 C 在准确率不占优时仍值得保留的理由。否则，单看准确率，B 臂通常不会输。</p>
<p>需要的话，我可以帮你把这个设计落成具体的实验配置文件（臂定义、预算参数、指标计算脚本的接口）。</p>

</td><td valign="top">
<p>首先，让我们做出判断：这项实验值得进行，但我们需要区分“第二轮提供证据”与“证据本身的实用性”。最小设计是一种2×2对照设计；标记总数和检索次数都是固定的。我们将重点关注最终答案的准确性，以及第一轮的独立答案的多样性，同时考察第二轮是否真的改变了答案，以及所使用证据的比例。</p>
<p><strong>控制设计</strong></p>
<p>共有四种条件：相同的问题集、相同的模型，以及相同的随机种子：</p>
<ol>
<li>无证据：在三个轮次中均不提供任何证据。</li>
<li>仅在第一轮提供证据：在第一轮提供证据，后续轮次保持相同条件。</li>
<li>仅在第二轮提供证据：第一轮给出独立答案，第二轮提供证据。这就是目标条件。</li>
<li>两轮都提供证据：第一轮和第二轮都提供相同的证据集。</li>
</ol>
<p>关键的比较点是3对1：延迟提供证据是否比完全不提供证据更有意义；3对2：延迟提供是否比从一开始就提供证据更好；4对2和3：反复使用证据是否能带来额外好处。1则作为基准，用于验证证据的整体效果。</p>
<p><strong>预算分配</strong></p>
<p>每个问题的总预算是固定的，而非按轮次分配。具体分配方式如下：</p>
<ul>
<li>输入标记总数和输出标记总数的上限是固定的；四种条件均相同。</li>
<li>检索次数以及每次检索返回的文档数量，以及截断长度都是固定的。在条件1中，不进行检索，但节省的预算会被转化为等效的讨论轮次或更长的单轮输出，因此“无证据组”的计算资源并不少于其他组。</li>
<li>智能体的数量和轮次数量都是固定的；每轮有三个智能体。</li>
<li>温度、最大生成长度和摘要提示均相同；只有证据注入的时间不同。</li>
<li>每个问题使用多个随机种子（例如3个种子），报告的是平均值，而非个体结果。</li>
</ul>
<p>如果条件1无法用相同的预算完成，应明确说明“无证据组的预算较低”，结论应限制在“在相同轮次数量下”。</p>
<p><strong>需测量的指标</strong></p>
<p>主要指标：使用固定评分标准或人工盲评估来衡量最终总结答案的准确性，评估者不知道具体条件。</p>
<p>次要指标：</p>
<ul>
<li>第一轮中三个智能体答案的一致性率。如果第一轮的表现稳定，那么第二轮的修正空间就会很小。</li>
<li>第二轮答案与第一轮的变化率，以及“从错误变为正确”和“从正确变为错误”的比例。这是评估机制的核心。</li>
<li>证据使用率：在第二轮回答中明确引用证据的比例。</li>
<li>使用证据后的准确性：使用证据后，回答是否仍然正确。</li>
<li>答案的多样性：第一轮中不同答案的数量，以此判断是否真的存在独立的回答。</li>
</ul>
<p><strong>哪些结果表明应停止实验</strong><br />
如果出现以下情况，建议停止实验或缩小实验范围：</p>
<ul>
<li>多个种子实验中，条件3的准确率与条件1相比几乎没有提升，且置信区间为零。</li>
<li>条件3明显低于条件2，说明延迟提供证据导致信息损失，机制存在错误。</li>
<li>第二轮的变化率非常低，且“从正确变为错误”的比例至少与“从错误变为正确”相等，说明证据未被有效利用或存在噪声。</li>
<li>证据使用率极低，表明智能体实际上没有阅读证据，实验所测量的机制并非预期中的机制。</li>
<li>改进仅出现在少数问题上，而这些问题在第一轮中已存在显著分歧；这表明好处来自个别案例，而非稳定的机制。</li>
</ul>
<p>如果条件3的准确率相对于条件1有稳定且积极的提升，但在条件2中没有优势，那么结论应为“证据是有用的，但延迟提供它不会带来额外价值”，而非“第二轮提供的证据是有用的”。</p>
