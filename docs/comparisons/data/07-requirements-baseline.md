先问最关键的 5 个，够定第一版骨架：

1. **哪个聊天客户端？**  
   是网页版（如 WhatsApp Web / Slack Web / Discord Web）还是原生桌面应用？这决定我是做浏览器扩展、桌面壳注入，还是读本地数据库/API。

2. **“回答太绕”怎么判定？**  
   第一版你希望是：手动触发（选中/快捷键）→ 显示更好读版本，还是自动检测长/复杂回答后提示？自动判定会显著增加复杂度。

3. **“更好读的版本”由谁生成？**  
   本地小模型、调用云端 API、还是规则化改写（分段/列点/去冗余）？这直接影响“数据留在本地”的可行性和实现量。

4. **显示形态？**  
   是在原消息旁内联替换/展开，还是侧边栏/浮层显示？是否需要保留原文对照？

5. **开关粒度？**  
   只要一个总开关，还是按会话/按消息临时开关？第一版建议总开关 + 单条手动触发，你确认下是否接受。

你回答这 5 个后，我再问第二轮（存储、权限、失败降级），不会一次堆太多。
