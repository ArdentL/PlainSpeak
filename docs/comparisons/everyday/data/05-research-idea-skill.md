这个想法具体解决的是“讨论成本花在分歧上”的问题：每题都讨论会把调用花在本来就会一致的题上，而先独立回答、只在答案不一致时触发讨论，能把讨论预算集中到真正有分歧的样本。它可能带来的收益有两块：一是总调用次数下降，二是分歧样本上的准确率接近或超过全量讨论。最容易失败的地方是：答案不一致不等于讨论能纠正，很多分歧是两边都错或一方错但理由不足以说服对方，讨论后可能维持原判甚至把对的带错；另外“答案不一致”的判定口径（精确匹配还是归一化后匹配）会直接改变触发率和成本，口径太严会退化成全量讨论，太松会漏掉该讨论的样本。

明天能跑的最小实验：

1. 选一个已有标注答案的小数据集，比如 100–300 题，固定同一模型和提示词。
2. 跑三个条件：A 只独立回答（取第一个 Agent 或任一固定 Agent）；B 全量两轮讨论；C 你的方案：先独立回答，答案不一致才讨论，一致则直接采用。
3. 记录每题：两 Agent 初始答案是否一致、C 是否触发讨论、A/B/C 的最终答案是否正确、总调用次数。
4. 主看三个数：C 相对 B 的调用节省比例；C 与 B 的准确率差；在“初始不一致”子集上，讨论前后准确率变化（讨论救回多少、带错多少）。
5. 答案匹配先做一层归一化（去空格、统一大小写、数字格式），并同时报告精确匹配和归一化匹配下的触发率，避免口径把结论带偏。

判断标准可以提前定：如果 C 的调用明显低于 B，且准确率下降在可接受范围内（比如不超过 1–2 个百分点），这个方向就值得继续；如果分歧子集上讨论的净收益接近零或为负，失败点就在“讨论能否纠正分歧”，需要换讨论策略而不是继续省调用。
