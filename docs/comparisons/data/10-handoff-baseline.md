# 交接说明：应用偶发卡顿排查

## 一、背景与现象
- 用户反馈：应用**偶发变卡**，**重启后可恢复**。
- 本次会话仅做了**只读检查**，未修改驱动、未调整网络设置。

## 二、已做过的检查与观测数据
- 卡顿发生时资源概况：
  - CPU 约 **18%**
  - 内存占用 **22GB / 32GB**
  - GPU 利用率约 **5%**
- 已保存日志：`logs/slow-session.log`（项目内路径）。

## 三、尚未确定 / 未做的事
- **未采集卡顿期间的进程级记录**（如各进程 CPU/内存/IO、线程栈等），因此**卡顿根因尚未定位**。
- 现有数据（CPU 18%、GPU 5%、内存 22/32GB）不足以指向具体瓶颈，不能据此下结论。
- 未验证驱动、网络配置是否相关（本次未改动，也未做对比测试）。

## 四、下一步建议
1. **复现一次卡顿**，并在复现期间采集**进程级记录**（进程/线程级 CPU、内存、IO、必要时抓栈）。
2. **对齐时间戳**：将进程级采集记录与 `logs/slow-session.log` 的时间轴对齐，确认卡顿窗口内哪些进程/操作异常。
3. 基于对齐结果再判断是否与驱动、网络或其他因素相关，避免在无证据前改动配置。

## 五、注意事项
- 保持只读排查原则，未定位前**不要随意改驱动或网络设置**。
- 复现时请记录卡顿起止时间点，便于与日志时间戳比对。
