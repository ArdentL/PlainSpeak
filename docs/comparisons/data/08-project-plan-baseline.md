下面按“两人、两周、本地文本改写插件、已有可运行小翻译模型、聊天客户端有公开插件接口”来给一个可执行的分工与交付计划。默认你们做的是**本地改写/翻译插件**：选中文本或输入框文本 → 调用本地小模型改写 → 展示改写结果与原文对照 → 可开关 → 本地记录。第一版不做云同步。

---

## 1. 第一版范围锁定

### 必须做（P0）
1. **插件接入聊天客户端**
   - 通过公开插件接口注册命令/按钮/快捷键。
   - 能获取当前选中文本或输入框文本。
   - 能把改写结果回填或展示。
2. **本地模型调用**
   - 封装已有小翻译/改写模型为本地服务或进程内调用。
   - 支持超时、失败提示、取消。
3. **自动处理**
   - 触发后自动调用模型，不需要用户二次确认。
   - 可配置触发方式：选中文本后点击/快捷键/输入框按钮，三选一即可。
4. **原文对照**
   - 展示原文与改写结果并排或上下对照。
   - 支持“替换原文”“复制结果”“关闭”。
5. **开关**
   - 插件总开关。
   - 自动处理开关。
   - 开关状态本地持久化。
6. **本地记录**
   - 记录时间、原文、改写结果、是否替换、耗时、模型名。
   - 支持查看最近 N 条、清空记录。
   - 只存本地，不上传。
7. **基础验收与打包**
   - 可安装/加载插件。
   - 有 README：安装、启动本地模型、使用、已知限制。

### 明确不做（P1/P2 延后）
- 云同步、账号体系。
- 多模型管理/模型市场。
- 复杂改写风格预设（正式/口语/简洁等可先硬编码一个默认 prompt）。
- 历史记录搜索、导出、统计图表。
- 多人协作、权限。
- 自动更新。

## 2. 两人分工建议

假设两人分别为 A、B，尽量按“客户端插件层”和“本地模型/记录层”切，减少互相阻塞。

### A：插件与交互负责人
- 聊天客户端插件接口调研与最小接入 demo。
- 获取选中文本/输入框文本。
- 触发入口：按钮/快捷键/命令。
- 原文对照 UI。
- 替换/复制/关闭交互。
- 总开关、自动处理开关的 UI 与状态同步。
- 插件打包、安装说明。
- 端到端联调主责。

### B：本地能力与数据负责人
- 本地模型调用封装：启动、请求、超时、取消、错误码。
- Prompt 模板与输入长度限制。
- 本地记录存储：schema、写入、读取最近记录、清空。
- 记录查看 UI 或简单列表接口（可与 A 约定由 A 接 UI）。
- 性能与稳定性：冷启动、并发限制、失败重试策略（第一版可不重试）。
- 本地隐私说明：确认无网络上传。

### 共同
- 第 1 天共同定接口契约。
- 每天一次 15 分钟同步。
- 验收由非主责方交叉验收。

## 3. 两周交付计划

按 10 个工作日算。

### Day 1：范围与契约
**目标**：冻结第一版范围和接口。
- 共同确认：
  - 触发方式只选一种主路径，建议“选中文本 + 快捷键/按钮”。
  - 原文对照展示形态：弹窗或侧栏，选一个。
  - 记录字段：`id, ts, source, result, replaced, latency_ms, model`。
  - 插件与本地模型通信方式：HTTP localhost 或 stdio，选一个。
- A 输出插件接口调研结论和最小 demo 计划。
- B 输出模型调用封装接口和记录 schema。
- **验收**：一页接口契约文档，双方确认。

### Day 2-3：最小闭环
**目标**：能选中文本 → 调本地模型 → 看到结果。
- A：插件注册、获取文本、触发调用、展示纯文本结果。
- B：本地模型服务可启动，提供 `/rewrite` 或等价调用，返回结果和耗时。
- **验收**：
  - 在聊天客户端选中一段文本，触发后 5 秒内看到改写结果。
  - 模型失败时有明确错误提示。
  - 不要求对照 UI 和记录。

### Day 4-5：原文对照与替换
**目标**：完成核心交互。
- A：原文/结果对照 UI，替换原文、复制、关闭。
- B：支持取消请求、超时、输入长度限制；返回稳定错误码。
- **验收**：
  - 对照区原文与结果都可见。
  - 点击替换后输入框/选中区域内容正确变更。
  - 超时或取消不会卡死 UI。
  - 连续触发 10 次无崩溃。

### Day 6-7：开关与本地记录
**目标**：完成 P0 剩余功能。
- A：总开关、自动处理开关、状态持久化；记录查看入口。
- B：记录写入、读取最近 50 条、清空；确保只写本地。
- **验收**：
  - 关闭总开关后触发无效或有明确提示。
  - 关闭自动处理后不自动调用，或按约定行为执行。
  - 重启客户端后开关状态保留。
  - 记录包含时间、原文、结果、是否替换、耗时。
  - 清空记录生效。
  - 断网情况下功能正常，确认无云请求。

### Day 8：联调与边界
**目标**：修主流程问题。
- 共同跑场景：
  - 空文本、超长文本、特殊字符、多语言混排。
  - 模型未启动、模型崩溃、请求超时。
  - 快速连点、重复触发。
- **验收**：P0 场景清单全部通过或有明确已知问题记录。

### Day 9：验收与打包
**目标**：可交付安装包。
- A：打包、安装说明、README、已知限制。
- B：本地模型启动脚本、依赖说明、记录文件位置说明。
- 交叉验收：A 验记录与模型失败路径，B 验插件交互与开关。
- **验收**：
  - 干净环境按 README 可安装并跑通主流程。
  - 验收清单签字/勾选。

### Day 10：缓冲与发布
- 只修 P0 阻塞问题。
- 冻结版本，打 tag，写 release note。
- 不新增功能。

## 5. 时间不够时砍什么

按“先砍体验增强，再砍非核心路径，最后才动核心闭环”的顺序：

### 第一优先级可砍
1. **自动处理开关的细粒度配置**：只保留总开关 + 一个自动处理开关，不做触发方式配置。
2. **记录查看 UI 的丰富度**：只做最近 20 条纯文本列表，不做搜索/导出/分页。
3. **复制结果按钮**：保留替换和关闭即可。
4. **多语言/多风格 prompt**：只保留一个默认改写 prompt。

### 第二优先级可砍
5. **取消请求**：只保留超时，不做手动取消。
6. **记录中的耗时/模型名**：只留时间、原文、结果、是否替换。
7. **快捷键**：只保留按钮触发。
8. **错误码细分**：统一“模型调用失败，请检查本地服务”。

### 最后才砍（会影响第一版定义，需双方确认）
9. **原文对照从并排改为上下简单展示**：功能仍在，体验降级。
10. **自动处理改为“点击后自动处理”而非“选中即处理”**：仍算自动处理，但触发更保守。
11. **本地记录改为只记录最近 10 条且不可查看，仅落盘**：不建议，因为“本地记录”是第一版明确要求，砍到不可查看会偏离验收。

### 不建议砍
- 本地模型调用闭环。
- 原文对照。
- 总开关。
- 本地记录落盘。
- 无云同步的隐私确认。

## 6. 关键风险与应对

1. **聊天客户端插件接口能力不足**
   - Day 1 必须验证：能否获取选中文本、能否回填、能否弹自定义 UI。
   - 若不能回填，降级为“展示结果 + 手动复制”，但需提前确认是否可接受。

2. **本地模型冷启动慢**
   - Day 2 测冷启动时间。
   - 若超过 5 秒，增加“模型预热”说明或启动脚本常驻。

3. **两人接口不一致**
   - Day 1 冻结契约，之后变更需双方确认。
   - 用固定 mock 返回让 A 不被 B 阻塞。

4. **第二周才发现插件接口限制**
   - 把最高风险验证放在 Day 1-2，不要先做 UI。

## 7. 一句话执行建议

**Day 1 先验证插件能否取文本和回填，Day 2-3 打通“选中→本地模型→结果”，Day 4-5 做对照与替换，Day 6-7 做开关与记录，Day 8 联调，Day 9 打包验收，Day 10 只修阻塞。时间不够先砍记录 UI 丰富度、复制按钮、快捷键和细粒度配置，不砍本地闭环、对照、总开关和记录落盘。**
