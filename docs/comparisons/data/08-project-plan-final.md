# 两周内本地文本重写插件：任务分配与交付计划

## 先明确第一版边界

第一版仅包含四项功能：**自动处理、原文对比、切换开关以及本地记录**。不包含云端同步功能。该插件通过聊天软件的公共插件接口连接，重写工作由用户现有的本地小翻译模型完成。

建议将“自动处理”功能定义如下：当用户在软件中选择文本或触发插件时，插件自动调用本地模型进行重写，然后将结果返回或显示出来。在初版中不要实现完全自动化，以监控所有输入操作，否则界面兼容性和意外触发会耗费大量时间。

## 任务分配

根据每个人的能力进行分工。以下为默认计划；可根据实际技能调整角色分工：

**A：插件与客户端集成**
- 连接聊天软件的公共插件接口，完成插件注册、触发点设置及结果返回功能。
- 实现切换开关功能：明确插件是否启用/禁用，以及是否自动执行单次处理。
- 显示原文与重写结果进行对比。
- 负责端到端集成及客户端接受度测试。

**B：本地模型服务与记录**
- 封装对本地小翻译模型的调用：输入清洗、重写提示、超时及错误处理。
- 实现本地记录功能：保存原文、重写结果、处理时间及成功状态，并存于本地文件或数据库。
- 提供本地接口让插件调用，确保当模型不可用时插件能提供备用提示而非冻结。
- 负责模型与记录功能的测试。

**共同任务**：第一天共同确定接口契约（请求字段、响应字段、错误代码），然后各自独立开发，每天进行简短同步。

## 时间规划

**第1天：确定契约并运行最小工作流**
- 共同确定插件调用本地服务的接口格式及记录数据结构。
- A运行客户端插件的最小示例；B运行模型调用的最小示例。
- 测试阶段：A可在客户端触发模拟重写操作并返回结果；B可返回文本片段的重写结果。

**第2–4天：各完成核心模块**
- A完成插件触发点、切换开关及原文对比显示功能。
- B完成剩余模块。 完整的模型封装功能，能够处理超时/失败情况，并生成本地记录。
- 验收标准：该模块可独立运行，接口输出符合约定要求。

**第5-6天：集成测试**
- 连接真实模型，确保“触发→重写→显示对比→生成记录”整个过程正常运作。
- 验收标准：选择10篇代表性文本，检查每个片段的重写结果是否正确，原始文本与重写结果是否匹配，以及记录是否完整。

**第7-8天：错误与边缘情况处理**
- 测试模型超时、模型无响应、客户端重复触发以及开关关闭时的处理情况。
- 验收标准：所有错误都应给出明确的警告或安全的降级处理；不得出现崩溃或脏记录。

**第9-10天：验收与缺陷修复**
- 检查验收清单上的每一项，修复阻碍功能的缺陷。
- 验收标准：所有项目均通过，或明确指出未通过的项目。

**第11-12天：缓冲时间**
- 仅修复缺陷并添加必要的说明，不添加新功能。

**第13-14天：最终交付**
- 整理安装/启动说明、已知限制条件以及记录文件位置。
- 验收标准：另一台机器可根据说明正常运行。

## 验收清单

1. 插件可在客户端启用/禁用，禁用后不会进行任何处理。
2. 触发后，本地模型自动被调用以进行重写，结果可清晰查看。
3. 原始文本与重写结果并排或垂直显示，便于区分。
4. 每个成功处理步骤都会生成包含完整字段的本地记录，且可读取该记录。
5. 模型超时或失败时会显示警告，客户端不会冻结，也不会生成错误记录。
6. 多次连续触发不会导致结果混乱或重复记录。
7. 在干净环境中，根据交付说明可一次性完成完整处理。

## 时间有限时应删除的内容

按以下顺序删除，从最后一项开始：

1. **删除显示样式**：仅保留纯文本对比，不添加高亮、差异显示或折叠功能。
2. **删除记录的详细信息**：仅保留原始文本、结果、时间以及成功/失败状态，不添加搜索、导出或接口清理功能。
3. **删除自动处理功能**：从“选择后自动处理”改为“手动处理一次”，但保留开关功能。
4. **砍模型端的最后处理步骤**：不对长文本进行分割，也不进行多轮重写；仅确保能够使用单个文本片段。

**不得移除任何功能**：切换功能、原始文本对比、本地记录的基本写入功能以及故障提示功能。这四项正是第一个版本的核心功能；移除这些功能意味着项目无法完成。

如果系统在整合测试10天后仍无法正常运行，就停止添加新功能。利用剩余时间确保最低限度的功能能够正常运作，并将所有已知缺陷记录下来，而不是继续添加更多模块。
